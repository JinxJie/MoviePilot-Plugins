# 栖影自动签到（MoviePilot V3）

V3 原生插件 v3.0.2：从用户已登录浏览器获取会话 Cookie，在 MoviePilot 插件配置中填写；默认关闭定时任务，支持手动执行、Cron 定时签到、系统代理与结果通知。先通过 `/api/auth/me` 只读预检会话并检查 `data.checkin_today`，站点确认今日已签到则跳过；明确未签到才执行不带请求体的 `POST /api/account/checkin`（依据用户浏览器 Network 中一次成功记录）。单实例内签到结果未知时留下当日待核对标记，下次运行先重新查询站点状态；无法确认状态时不发送签到请求。不同实例并行运行不保证互斥，请勿同时部署多个实例。

**Browserless 备用模式（默认关闭）：** 在设置页的独立区域开启开关，填写受信任服务的完整 HTTPS `/function?token=...` 地址，再保存配置。关闭时沿用现有直连/代理路径；开启后本次签到的站点预检与签到请求均由 Browserless 的远程浏览器执行，不会因普通路径失败自动切换或重发。站点 Cookie 会传给 Browserless 服务，请使用自己的可信服务，不要在聊天或日志中粘贴完整地址。插件的系统/自定义代理仅用于连接 Browserless 服务，**不改变远程浏览器访问栖影时的出口 IP**。先在自己的服务上验证连接和站点读取能力，再考虑开启定时任务。Browserless 不能代替人工完成登录或人机验证。

**验收边界：** 已通过无凭据模拟响应的离线测试；用户已验证原有 3.0.1 路径在站点签到成功，但 Browserless 模式尚未通过真实服务或 MoviePilot 宿主验证。登录环节需要人工在浏览器完成人机验证，插件不提供自动登录或验证码绕过。站点接口或保护机制变化可能导致失败；请以站点记录为准。

**安全提醒：** 此前会话 Cookie 曾发到群聊，建议在站点撤销旧会话、重新登录；新 Cookie 仅保存在自己的 MoviePilot 配置，不发送到聊天。

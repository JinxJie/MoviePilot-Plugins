# 栖影自动签到（MoviePilot V3）

V3 原生插件 v3.0.5：从用户已登录浏览器获取会话 Cookie，在 MoviePilot 插件配置中填写（须包含非空 `hdh_session` 项）；默认关闭定时任务，支持手动执行、Cron 定时签到（配置期校验，时区取宿主 TZ）、系统代理与分行结果通知。首页通过只读请求展示账户信息和今日状态，签到记录绑定站点账号、按日期去重、最多保留最近 30 条；旧版本未绑定账号的历史记录仍会展示（标注"未绑定账号"），但不计入新账号累计、也不复用其数字。每次运行绑定同一份不可变运行上下文（配置快照、取消标志与代际号），配置重载或停止会取消待执行任务，并与在途签到的提交边界互斥：未进入提交的在途任务被中止，提交中的签到先完成再换代（重载至多等待一个提交周期，超时会明确记录）；跨日未核对的签到尝试单独保留，不会静默丢失。先通过 `/api/auth/me` 只读预检会话并检查 `data.checkin_today`，站点确认今日已签到则跳过；明确未签到才执行不带请求体的 `POST /api/account/checkin`（依据用户浏览器 Network 中一次成功记录）。单实例内签到结果未知时留下当日待核对标记，下次运行先重新查询站点状态；无法确认状态时不发送签到请求。定时任务按宿主约定返回 (成功, 消息) 元组，失败会如实进入调度历史。不同实例并行运行不保证互斥，请勿同时部署多个实例。

**网络路径：** 关闭系统代理即为真实直连——会话显式禁用环境代理（`trust_env=False`），只按插件当前选择的系统代理或自定义代理配置出口；会话 Cookie 由限定站点域名的 Cookie jar 管理并标记 secure，自动重定向已禁用（站点接口出现跳转按未确认结果处理，不携带会话跟随），站点轮换 Cookie 可正常生效。开启系统代理但未读取到配置时会明确提示。Cron、签到日期与通知时间统一使用宿主配置时区。

**Browserless 备用模式（默认关闭）：** 在设置页的独立区域开启开关，填写受信任服务的完整 HTTPS `/function?token=...` 地址，再保存配置。关闭时沿用现有直连/代理路径；开启后本次签到的站点预检与签到请求均由 Browserless 的远程浏览器执行，不会因普通路径失败自动切换或重发。Browserless 每次调用都是独立浏览器实例；脚本按远端运行时（Puppeteer `page.cookies` / Playwright `page.context().cookies`）尝试导出站点下发的最新 Cookie 并注入下一次调用，保持预检与签到之间的会话连续。该导出路径按两种运行时分别实现并通过嵌入脚本可执行测试，但尚未经真实 Browserless 服务验证；导出不可用时自动退回空回传，不影响原流程。这仍不能保证两次调用使用相同出口 IP。站点 Cookie 会传给 Browserless 服务，请使用自己的可信服务，不要在聊天或日志中粘贴完整地址。插件的系统/自定义代理仅用于连接 Browserless 服务，**不改变远程浏览器访问栖影时的出口 IP**。先在自己的服务上验证连接和站点读取能力，再考虑开启定时任务。Browserless 不能代替人工完成登录或人机验证。

**验收边界：** 已通过无凭据模拟响应的离线测试（含调度返回约定、账号隔离、跨日待核对、Cookie 轮换回放、取消/停止同步等新行为）；原有路径经用户在站点实测签到成功。3.0.5 的新增修复尚未在 MoviePilot 宿主实机验收，Browserless 模式也未通过真实服务或宿主验证。登录环节需要人工在浏览器完成人机验证，插件不提供自动登录或验证码绕过。站点接口或保护机制变化可能导致失败；请以站点记录为准。

**安全提醒：** 此前会话 Cookie 曾发到群聊，建议在站点撤销旧会话、重新登录；新 Cookie 仅保存在自己的 MoviePilot 配置，不发送到聊天。
